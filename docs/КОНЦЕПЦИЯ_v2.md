# «Учёт ТО» v2 — упрощение: один главный экран

Это контракт на переделку интерфейса. Расчёты, база, импорт/экспорт и API v1 (`docs/SPEC.md`, разделы 2–6) **не меняются**,
кроме двух добавок (раздел 9). Меняется то, что видит механик (раздел 7 SPEC заменяется этим документом).

## 1. Идея

Механик знает одну вещь — таблицу: строка = машина, кремовые ячейки — куда вписывать, белые — что программа посчитала.
В v1 эта таблица была разрезана на четыре экрана (Парк, Показания, Журнал, Отчёты) — наследие Google-таблицы с отдельными листами.
В v2 — **один главный экран, одна таблица**, в которой:

- видно, какая машина и что у неё с ТО (цвет строки + «осталось / просрочено»);
- прямо в строке вписывается новое показание счётчика (кремовая колонка), а у машин без внесённого ТО — последнее ТО;
- видно, что с машиной делали в последний раз (колонка «Что делали»), и одной кнопкой добавляется запись;
- кнопка «ТО сделано» — в каждой строке.

Всё второстепенное (история, шины, узлы, фото, параметры) живёт в карточке машины, из которой очевидно, как вернуться.
Служебные экраны (Заказ-наряд, Машины, Шины, Узлы, Настройки) остаются отдельным блоком меню.

## 2. Сценарий механика → экран

| Шаг | Что делает механик | Где в v2 |
|---|---|---|
| Заехал на вахту | Вбил показания всем машинам за один раз | Главная: колонка «Новое показание», Enter — следующая строка, внизу «Сохранить всё». Строки сразу краснеют |
| Увидел список на ТО, заказал масло/фильтры | — | Кнопка «Список на ТО» (экран «Список на ТО»: машины + что заказать по регламенту, печать) |
| Что сделали без него | Внёс, какое ТО и на каком показании сделано | Кнопка «ТО сделано» в строке (вид ТО, показание на момент ТО, показание сейчас). У машин, где ТО вообще не внесено, — кремовые поля прямо в колонке «Последнее ТО» |
| Сделал ТО сам | Отметил ТО-1/2/3, показание ТО и показание сейчас | Та же кнопка «ТО сделано» |
| Каждый вечер | Записал, что сделано за день (ремонт, колодки, масло) | Кнопка «+» в строке → запись: дата, что делали, при ремонте — когда вышла. Текст виден в колонке «Что делали» |
| Машина вышла из ремонта | — | Кнопка «Закрыть ремонт» в строке |
| Раз в день (по желанию) | Накинул суточную наработку тем, кто на линии | Кнопка «Накинуть за день» (диалог как в v1) |

## 3. Навигация (боковая панель)

```
Главная            #/fleet     — главная таблица (по умолчанию)
Список на ТО       #/plan      — машины на ТО + что заказать + заявки (бывший «План ТО и заказ»)
— Служебное —
Заказ-наряд        #/workorder
Машины             #/machines  — справочник
Шины               #/tyres
Узлы               #/units
—
Настройки          #/settings
```

Удаляются экраны и файлы `pages/readings.js`, `pages/journal.js`, `pages/reports.js`.
Старые адреса не ломаются: `#/readings` и `#/reports` → `#/fleet`; `#/journal?machine_id=N` → `#/machine/N`; `#/journal` без машины → `#/fleet`.
Перед «Служебное» в панели — маленькая подпись-заголовок (muted, 11–12px, uppercase), а не просто разделитель.
Карточка машины подсвечивает пункт «Главная». Поиск машины в верхней строке остаётся.

## 4. Главная (`pages/fleet.js`, переписывается)

Данные — `GET /api/fleet` на сегодня (дата отчёта из v1 убрана; `?date=` в API остаётся для карточки и тестов).

### 4.1 Верх экрана

Строка 1 (toolbar): `[Накинуть за день]` (icon calendar-plus) · `[Список на ТО]` (primary, icon calendar-check → `#/plan`) · `[Печать]` (icon printer)
· spacer · поле поиска «Гар. №, модель, госномер» · select «Все участки».

Строка 2 — **чипы-фильтры** (кнопки-переключатели, одна активна или ни одной; цвет по status-chip, число — счётчик):

Клик по шапке — обычная сортировка по колонке; «Сбросить» возвращает порядок по умолчанию. Клик по строке → карточка (клики по полям ввода, кнопкам и select'ам не должны открывать карточку).
Цвет строки: overdue → `row-red`, soon → `row-amber`. `fill: true`, `inputNav: true`.

### 4.3 Панель сохранения (внизу, липкая, появляется, когда есть хоть одно заполненное поле)

`Показаний: 3 · последних ТО: 2` · «Дата показаний» `dateInput` (сегодня, max сегодня) · spacer · `[Очистить]` (ghost) · `[Сохранить всё]` (accent, big, icon check). Ctrl+S — сохранить.
Сохранение — `POST /api/readings/bulk {date, items, baseline, force}` по правилам readings.js v1:
строки с ошибкой ввода не отправляются (тост, фокус на первую); 409 → `ui.confirm` со списком предупреждений (одинаковые у многих машин сворачивать: «текст — у 7 машин») → повтор с `force: true`;
`errors[]` ответа — строка остаётся с введённым и текстом ошибки под полем (`part` — какую часть очищать); успех — тост «Сохранено: показаний N, последних ТО M. Сейчас: просрочено X, скоро Y», поля очищаются, таблица перечитывается.
`ctx.setLeaveGuard` — пока есть несохранённое. Тихое авто-обновление (5 мин / при фокусе окна) — только если нет несохранённого ввода и нет открытых диалогов.

### 4.4 Печать

`[Печать]` → `ui.printPage('Машины и ТО на DD.MM.YYYY', {landscape: true})`: печатается таблица как есть (пустые кремовые поля — как бланк для обхода), без кнопок и чипов. Это заменяет «Отчёт за день».

### 4.5 Пустые состояния

Нет машин — как в v1 («Добавить машину»). `first_run` → `#/welcome`. Нет совпадений по фильтру — emptyState с кнопкой «Сбросить».

## 9. Добавки на сервере

### 9.1 `last_note` в MachineView (для колонки «Что делали»)

`last_note: {event_id, date, date_unknown, kind, kind_title, text, open} | null` — последняя по (`date` desc, `id` desc) запись машины с `source != 'auto'`, `kind != KIND_MARK`, `date <= D`.
`text` — первое непустое из `work`, `remarks`, `parts_used` (строка, обрезать до 300 символов). `open` — для Ремонт*/Простой* без `date_out`.
Реализация — в `services._load`/`_views` **одним запросом** с оконной функцией (`ROW_NUMBER() OVER (PARTITION BY machine_id ORDER BY date DESC, id DESC)`), чтобы число запросов не зависело от числа машин (SPEC 4.9, тест производительности остаётся ≤ 1.5 с).
Поле попадает во все ответы, где есть MachineView (fleet, card, view, plan). Тесты: в `test_services` — выбор последней записи, запасной текст, auto и отметки не считаются, записи позже D не считаются.

### 9.2 Фото машин

Файлы: `<папка данных>/photos/<machine_id>/<имя>`. В базе ничего не хранится (список — из папки). В резервные копии `backups/` фото не входят, но лежат в той же папке `data` (в Инструкции сказать).

| Метод и путь | Вход | Выход |
|---|---|---|
| GET `/api/machines/{id}/photos` | — | `[{name, size, mtime, url}]` по `mtime` (старые первыми); `url = /api/machines/{id}/photos/<name, percent-encoded>` |
| POST `/api/machines/{id}/photos?name=<имя файла, percent-encoded>` | тело — байты, `Content-Type: application/octet-stream`, лимит 25 МБ | `{name, size, url}` |
| GET `/api/machines/{id}/photos/{name}` | — | файл; `Content-Type` по расширению (jpg/jpeg → image/jpeg, png, webp, gif), `Cache-Control: no-store` |
| DELETE `/api/machines/{id}/photos/{name}` | — | `{ok: true}` |

Правила: машина должна существовать (иначе 404). Расширение — только jpg/jpeg/png/webp/gif (иначе 400 «Можно загружать только фото: jpg, png, webp, gif»); первые байты проверять по сигнатуре (JPEG `FF D8`, PNG, RIFF/WEBP, GIF8), несовпадение → 400.
Имя: взять базовое имя без пути, оставить буквы (латиница и кириллица), цифры, `. _ - ` и пробел, схлопнуть повторы, обрезать до 80 символов; пустое → `foto-YYYYMMDD-HHMMSS.<ext>`; занято → добавить `-2`, `-3`… Любая попытка `..`, `/`, `\` в `{name}` при GET/DELETE → 404.
`GET /api/machines/{id}/card` дополнительно отдаёт `photos: [...]` (тот же список), чтобы карточка грузилась одним запросом. `DELETE /api/machines/{id}?force=1` удаляет и папку фото.
Тесты в `test_api`: загрузка (валидный PNG из байтов), список, получение файла с правильным Content-Type, имя с кириллицей и пробелами, дубликат имени → `-2`, плохое расширение → 400, подделка расширения → 400, `..` → 404, удаление, удаление машины чистит папку.
