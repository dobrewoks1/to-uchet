# Учёт ТО

Программа для механика, который ведёт парк спецтехники. По каждой машине считает остаток до ТО по пробегу
или моточасам, подсвечивает просроченные и ближайшие, ведёт журнал ремонтов и простоев, печатает заказ-наряд
и список «что заказать» к ТО. Работает без интернета, ставится одним `.exe`, вся база — в одном файле рядом
с программой.

Сделана для парка из 93 машин дочерней компании РЖД и работает у заказчика. В репозитории — код без данных
заказчика: демо-база, скриншоты и примеры вымышленные.

![Главный экран: весь парк одной таблицей, просроченные ТО сверху](docs/img/fleet.png)

## Как появилась

Механик вёл журнал парка в Google-таблице (восьмая версия, записи с мая 2026). Таблица упёрлась в предел:
остаток до ТО считался в уме, пропущенные за вахту ТО терялись, а на вахте ноутбук часто без интернета.
Дальше по датам:

- **2 октября** — два разговора с механиком → [ТЗ](docs/ТЗ.md): 14 требований его словами
  («загорается красным — пора делать ТО», «зашёл, не высчитывал сам, а посмотрел: осталось столько-то»).
- **2–10 октября** — [спецификация](docs/SPEC.md) как контракт: схема базы, правила расчёта, API, экраны.
  По ней написана v1: четыре экрана, тесты на правила расчёта.
- **10 октября** — v2: четыре экрана сложились в [один главный](docs/КОНЦЕПЦИЯ_v2.md) после примерки на
  сценарий механика («заехал на вахту → вбил показания всем → увидел, кому пора»). Сборка, 32-битный `.exe`
  для Windows 7 на вахтовых ноутбуках, [руководство с картинками](docs/guide.md).

От первого разговора до сборки, готовой к передаче, — восемь дней.

## Что умеет

- Главный экран — весь парк одной таблицей: показания вводятся подряд (Enter — следующая машина), рядом
  остаток до ТО, пропущенные ТО и последняя запись; фильтры «Просрочено / Скоро / Нет данных / Не на линии».
- «ТО сделано» с циклом ТО-1 → ТО-2 → ТО-3. Показание на момент ТО вводится отдельно от текущего: ТО сделали
  без механика на 150 000, сейчас 153 000 → следующее на 160 000, осталось 7 000.
- «Накинуть за день» — суточная наработка всем, кто на линии. Расчётные показания помечены «≈» и уступают
  фактическим, как только те введены.
- Список на ТО с горизонтом по средней наработке и сводка «что заказать» по регламенту.
- Карточка машины: история, «как считается», шины, узлы, фото.
- Заказ-наряд и отчёт за день на печать или в PDF.
- Импорт из Excel с предварительным отчётом (что нашли, какие строки под вопросом) и без дублей; выгрузка
  всей базы обратно в Excel.
- Автокопии базы при запуске (не чаще раза в 6 часов, хранятся 30 последних), восстановление из копии,
  самовосстановление при повреждённом файле.

Руководство пользователя — [docs/guide.md](docs/guide.md).

## Решения и почему

| Решение | Почему |
|---|---|
| Только стандартная библиотека Python (`http.server`, `sqlite3`) + openpyxl; фронтенд — ванильный JS без сборки и без CDN | На вахте ноутбук без интернета и без прав на установку. Один `.exe`, ничего не скачивается и не ломается от обновления браузера |
| Окно — Edge или Chrome в режиме `--app` поверх локального сервера | Выглядит и ведёт себя как обычная программа без Electron; сервер слушает только `127.0.0.1` |
| Все расчёты — чистые функции на сервере (`app/logic.py`), фронтенд показывает готовые поля | Один источник правды, и каждое правило из ТЗ покрыто тестом |
| SQLite в режиме WAL, checkpoint после каждой записи, автокопии, самовосстановление | Базу носят на флешке и выключают питание не глядя; скопированный `to.db` должен быть целым |
| 32-битная сборка на Python 3.8 | На части вахтовых ноутбуков Windows 7 |
| Импорт таблицы v8 с «сухим прогоном» и защитой от дублей | Пять месяцев журнала нельзя было потерять или задвоить при переходе |
| «Если код и SPEC расходятся — прав SPEC» | Правило из спецификации: сначала меняется контракт, потом код |

## Как это делалось

Проект сделан в связке с Claude Code. Моя часть — разговоры с заказчиком, ТЗ и спецификация, примерка
интерфейса на его сценарий, проверка каждой сборки руками и тестами, руководство. Часть агента — код по
спецификации, тесты на правила из ТЗ, черновики документации. Правила для агента в этом репозитории —
[CLAUDE.md](CLAUDE.md).

## Запуск за минуту

Нужен Python 3.8+ и Edge или Chrome.

```
pip install -r requirements.txt
python run_dev.py --demo
```

Откройте http://127.0.0.1:8765/. При первом запуске `seed_demo.py` создаст в `demo-data/` вымышленный парк из
20 машин: просроченные и близкие ТО, ремонт, простой, консервация, шины, узлы. Даты считаются от сегодняшнего
дня, поэтому картина всегда одинаковая. Пересоздать демо-базу: `python seed_demo.py --force`.

Запуск как у пользователя (сервер + окно браузера в режиме приложения, данные в `data/`): `python -m app.main`.

## Тесты

```
python -m unittest discover -s tests -v
```

286 тестов: расчёт ТО и состояний (`test_logic`), сервисный слой (`test_services`), HTTP API вместе с защитой
от path traversal (`test_api`), импорт и экспорт xlsx (`test_xlsx`), нагрузка 250 машин × 400 записей журнала
(`test_perf`, отключается `TO_SKIP_PERF=1`). Те же тесты идут в GitHub Actions на Windows.

## Сборка `.exe`

- `build.bat` — один `dist\TO-Uchet.exe` (PyInstaller onefile, 64 бит). Нужен `.venv` с `openpyxl` и `pyinstaller`.
- `build-compat.bat` — 32-битный exe на Python 3.8 для Windows 7 SP1 / 8.1 / 10 / 11 (путь к Python — переменная `PY38`).
- `package.ps1` — zip для передачи пользователю: exe, база из `dist\data` (если есть), PDF-инструкция, README.txt.

Данные программа хранит в папке `data` рядом с exe: база `to.db`, копии `backups/`, фото `photos/`, журнал `app.log`.

## Формат импорта

Импорт рассчитан на книгу «Журнал учёта техники и ТО» версии 8; пример с синтетическими данными —
[examples/demo-v8.xlsx](examples/demo-v8.xlsx). На каждом листе строки 1–3 — заголовок и пояснения,
**строка 4 — шапка, данные с 5-й строки**. Листы узнаются по ключевым словам в шапке, так что формулировки
могут немного отличаться. Обязательны листы «Машины» и «Журнал», остальные — по желанию.

## Устройство

```
app/main.py        точка входа: выбор порта, один экземпляр, окно Edge/Chrome --app, автовыключение
app/server.py      http.server: JSON API /api/*, статика, загрузка файлов, защита путей
app/services.py    сценарии (сохранить показания, ТО сделано, накинуть за день, план, заказ-наряд…), 409 «нужно подтверждение»
app/logic.py       чистые функции расчёта: показание на дату, статус ТО, цикл ТО, состояния, длительности
app/db.py          SQLite: схема, миграции, справочники по умолчанию, резервные копии и восстановление
app/xlsx_io.py     импорт таблицы v8 (с dry run) и экспорт в xlsx (openpyxl)
app/static/        фронтенд: ванильный JS (ES-модули, без сборки и CDN), CSS, иконки Tabler
seed_demo.py       демо-данные: синтетическая книга v8 → штатный импорт в demo-data/to.db
tools/screenshots.py  скриншоты docs/img на демо-данных через headless Edge/Chrome
tests/             unittest, 286 тестов
docs/              ТЗ, SPEC (полная спецификация), концепция v2, руководство пользователя
```

Всё работает локально: интернет не нужен, единственная внешняя зависимость времени выполнения — openpyxl,
и та подключается только при импорте и экспорте. Подробности — в [docs/SPEC.md](docs/SPEC.md).

**In English.** Offline maintenance tracker for a field mechanic running a fleet of heavy equipment (trucks
counted in km, excavators and dozers in engine hours). It computes the remaining interval to the next service
from the last one done, highlights overdue and upcoming units, keeps a repair log, prints work orders and a
service shopping list, and imports/exports the customer's Excel workbook. Built for a 93-unit fleet of a Russian
Railways subsidiary and in production there. Stack: Python standard library (`http.server`, `sqlite3`) + openpyxl,
vanilla JS front end with no build step and no CDN, shipped as a single PyInstaller `.exe` (plus a 32-bit
Python 3.8 build for Windows 7). 286 unit tests. UI and docs are in Russian.
