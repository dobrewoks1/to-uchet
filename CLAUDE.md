# CLAUDE.md — правила работы агента в этом репозитории

Проект «Учёт ТО»: офлайн-программа для механика, который ведёт парк спецтехники. Контракт — `docs/SPEC.md`
(читать вместе с `docs/ТЗ.md` и `docs/КОНЦЕПЦИЯ_v2.md`). Если код и SPEC расходятся — прав SPEC; если SPEC
неполон — решать в духе ТЗ: максимально просто для механика, который не айтишник.

## Границы

- Зависимости: только стандартная библиотека Python + `openpyxl`. Фронтенд — ванильный JS (ES-модули), без
  сборки, без CDN, без фреймворков: программа работает на ноутбуке без интернета и прав на установку.
- Вся логика расчётов — в `app/logic.py` (чистые функции без базы и без «сейчас» внутри) и `app/services.py`.
  Во фронтенде расчёты не дублировать, он показывает готовые поля `MachineView`.
- Сервер слушает только `127.0.0.1`; запросы с чужим `Host` → 403. Так и оставить.
- Никаких данных заказчика: примеры, тесты, скриншоты и демо-база — только вымышленные (`seed_demo.py`).
  Фамилии, VIN, госномера и номера договоров в коде — только демо-значения.

## Как проверять

- `python -m unittest discover -s tests -v` — все 286 тестов зелёные до коммита; `TO_SKIP_PERF=1` пропускает
  нагрузочный тест.
- Новое правило расчёта: сначала тест в `tests/test_logic.py` на формулировку из ТЗ, потом код.
- Руками: `python run_dev.py --demo` и сценарий механика из `docs/КОНЦЕПЦИЯ_v2.md`, раздел 2
  (заехал на вахту → вбил показания всем → увидел, кому пора → отметил ТО → записал, что делал за день).

## Как менять

- Порядок: правка SPEC (раздел и формулировка) → код → тесты → `docs/guide.md`, если меняется экран.
- Скриншоты для `docs/img` снимаются на демо-данных: `tools/screenshots.py`.
- Интерфейс русский; подписи на экране — словами механика из ТЗ, а не терминами из кода.
- Сборка exe: `build.bat` (64 бит) и `build-compat.bat` (32 бит, Python 3.8, Windows 7). После правок
  `app/main.py` проверять обе.
